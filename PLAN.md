## 1. Goal

Merge `upstream/main` (zed-industries/zed) into our fork `dx-code` such that:

* **100 % of our local changes survive**, and
* **100 % of upstream's changes survive**,
* our local UI wins where the two genuinely conflict, and
* upstream functionality our UI has no surface for is **kept compiled and wired, just not
  surfaced** — never silently dropped.

`dev` has **no common ancestor** with `upstream/main` (fresh root commit `8dc3418ec1`). A plain
`git merge-tree` refuses ("unrelated histories"); the `--allow-unrelated-histories` form is
**meaningless** — it diffs against the **empty tree**, whose signature is "0 `content` conflicts +
thousands of `add/add`". That 0 is a *missing base*, not a hard merge.

The base was recovered by minimising `git diff --name-only <candidate> dev` over upstream history.
`git merge-tree --merge-base=<commit>` accepts a non-ancestor base, which is what makes this work.

## 3. Hard environment constraints

* **The G: safe-delete guard wedges `git merge`.** A merge that deletes a large number of files
  writes most of them and then stops permanently (`git.exe` Not Responding, CPU frozen) —
  reproduced 4×, including with the sandbox bypassed. The same interception explains
  `git update-ref` returning 0 while changing nothing.
* Therefore: **all resolution happens in the object DB + a scratch index. Zero worktree writes.**
  The guard cannot fire on a deletion that never happens.
* `core.autocrlf=true`, but the **index is LF throughout** (`git ls-files --eol` → `i/lf`).
* **`MSYS_NO_PATHCONV=1` is mandatory** for object paths like `upstream/main:.cargo/config.toml`
  (otherwise MSYS mangles them to `upstream\main;.cargo\config.toml`). Note that with it set, git
  can no longer open `/g/...` scratch paths — pass `G:/...` instead.
* Long foreground shell commands get SIGTERM'd at roughly 2 minutes. Run engines with
  `run_in_background` and make them **resumable**.
* Windows Python needs `G:/...` paths, never `/g/...`.
* Disk: ~48 GB free; the merged tree is only **448 MB** across 28 482 blobs, so materialising a
  scratch copy is cheap.

## 4. Machinery

```bash
export GIT_INDEX_FILE=G:/tmp/merge-idx2     # NOT merge-idx — see the lock trap below
export MSYS_NO_PATHCONV=1

# recompute the merge (in-memory; leaves worktree and refs alone)
git merge-tree --write-tree --merge-base=d8eb569cc5 merge-20260924 upstream/main
# -> 61ff6f4ddf14b258a6e11810345f59d51e6a5ce3   (257 CONFLICT records, 259 conflicted paths)

# seed the scratch index from merge-ort's own result (stage 0, conflict markers inline)
git read-tree 61ff6f4ddf
```

Apply a resolved file:

```bash
sha=$(git hash-object -w G:/tmp/mr2/<path>.resolved)
git update-index --add --cacheinfo 644,$sha,<path>
```

Remove a path:

```bash
git update-index --force-remove <path>
```

Finish (only when TODO.md is empty):

```bash
git write-tree
git commit-tree -p merge-20260924 -p upstream/main -m "merge: upstream Zed baee1ca6de into dx-code"
# then the user runs: git reset --hard <resolved>
```

Per-file context generated by the merge engine lives in `G:/tmp/mr2/<path>.{base,ours,theirs,merged}`
with a report at `/tmp/mf2_report.tsv` (cols: `rc`, `residual_hunks`, `ours_changed`,
`theirs_changed`, `direction`, `path`). **Both are on volatile storage — regenerate if missing**
(see `G:/tmp/merge-engine2.sh`).

### Traps

* **The G: guard blocks git's index writes too.** `git update-index` writes `<index>.lock` then
  **renames** it over the index; that rename is intercepted → `fatal: Unable to write new index
  file`. A SIGTERM'd run leaves a multi-MB orphan `.lock` that the guard **refuses to rename or
  delete** (verified with the sandbox bypassed). Hence `merge-idx2`. The guard is **intermittent** —
  a retry seconds later succeeded. Fallback: `C:` (17 GB free); the index need not live on the
  repo's drive.
* **`git merge-file`'s `-L` labels are positional, not auto-derived.** Passing `theirs base ours`
  while labelling `OURS BASE THEIRS` silently swaps the two sides in the review output. Confirm any
  disputed hunk with `git grep` against the tree, never by trusting the label.
* **`merge-tree --name-only` has NO rename detection.** Upstream renamed/split crates
  (`csv_preview`→`tabular_data_preview`, `gpui_macos`→`gpui_apple`, `git_ui`→`git_ui_core`+`picker`,
  `client/src/proxy`→new `http_proxy` crate, `util/src/rel_path`→new `path` crate), so `--name-only`
  reports ~114 phantom deletions. **The authoritative deletion measure is**
  `git diff -M --name-status merge-20260924 61ff6f4ddf` → A 437 · M 1446 · **D 53** · R 27.
* `git hash-object -w` prints an "LF will be replaced by CRLF" warning. It is **cosmetic** — the
  blob round-trips byte-exact (verified with `cmp`).

## 6. Resolution policy in detail

1. **Mechanical batch first** — accept our deletions where we deliberately have no such tree
   (`docs/**`), and accept upstream additions wholesale.
2. **Start from the dominant side, apply the other side's patch.** For each content conflict the
   engine records `direction`: if our change is smaller than upstream's, start from theirs and apply
   ours, and vice-versa. Residual hunks are exactly where the two sides genuinely overlap.
3. **Union where both sides added.** Many "conflicts" are one side adding a function and the other
   adding a different function in the same place — keep both.
4. **Local UI wins, upstream behaviour is re-attached.** Where upstream restructured code our UI
   rewrote, keep our structure and port upstream's semantic change onto it.
5. **Never lose upstream capability.** If our UI has no surface for it, keep it compiled and wired
   but unsurfaced.
6. **`Cargo.lock` is regenerated, never hand-merged** (353 of the hunks).
7. **Re-validate cross-file invariants after every manifest edit.** merge-ort resolves *per file* and
   cannot see that one file's change invalidates another's. Real instance found here — `pathdiff`:

   | | root `Cargo.toml` | `crates/editor/Cargo.toml` |
   |---|---|---|
   | base | `pathdiff = "0.2"` present | absent |
   | **ours** | unchanged | **added** `pathdiff.workspace = true` |
   | theirs | **removed** the dep | unchanged |
   | merge-ort | took theirs' removal ✓ | kept ours' addition ✓ |

   Both decisions are locally correct and jointly **inconsistent**. Since our fork *uses* `pathdiff`
   (`crates/editor/src/items.rs`), the fix is to **restore the workspace dep** — our work survives and
   nothing of upstream's is removed. `cargo metadata --no-deps` + `check_ws_inherit.py` are the
   detectors. Watch the same shape in `[workspace.package]`, `[workspace.lints]`, feature
   unification, `Cargo.lock`, and string-keyed registries like `assets/settings/default.json`.

## 7. Structural decisions already taken (with rationale)

* **`.cargo/config.toml` restored from upstream.** It is *not* housekeeping: it carries
  `--cfg tokio_unstable` and `--cfg windows_slim_errors`, and `tokio_unstable` appears **nowhere**
  in our tree. The merged tree carries upstream code, so the file is build-critical. It does **not**
  set `target-dir`, so the justfile's `build_target_dir` pin is unaffected.
* **`crates/http_proxy/` took upstream's version.** Ours is a *strict subset* — an earlier stage of
  the same crate (our `http_proxy.rs` declares only `mod allowlist` and says "this crate grows over
  a short stack of PRs"; upstream adds `pinned_host` + `proxy`, 11 deps vs our 2). Taking theirs
  preserves both sides.
* **`crates/media`, `crates/panel`, `crates/csv_preview` dropped from the workspace.** All three are
  *upstream* crates that upstream deleted between June and September; we had never modified them
  (`ours == base` for every file). Real extern-crate usage was only two lines:
  `gpui_macos/src/screen_capture.rs` (upstream replaced it with `objc2_core_media`) and
  `git_ui/src/git_panel.rs` (`use panel::PanelHeader`, upstream moved it). The `panel::` hits in 54
  files are `workspace.panel::<T>(cx)` **method calls**, and `media::` in `crates/repl` is
  `jupyter_protocol::media::` / `runtimelib::media::` — submodule paths, not crates.
* **Root `Cargo.toml` resolved** (10 conflict blocks): members = union minus dead crates; workspace
  deps = union of keys with ours preferred on a clash; `objc2-app-kit` features = union of both
  sides. Validator: `G:/tmp/check_cargo.py` (0 missing members, 0 missing path-deps, 0 duplicate keys).

## 8. Verification strategy

* `G:/tmp/check_cargo.py <Cargo.toml> <index paths>` validates the whole manifest graph cheaply:
  every `members` entry and every `[workspace.dependencies] path=` must exist in the index.
* `G:/tmp/check_ws_inherit.py <index>` catches the **cross-file** class (§6.7): every
  `X.workspace = true` in every member must resolve against the root `[workspace.*]` tables. It reads
  manifests straight out of the scratch index, so there is no worktree-sync doubt.
* **`cargo metadata --no-deps` is the cheap end-to-end check** — no network, no build. It is the only
  thing that reliably catches the cross-file manifest class, and it found `pathdiff` in seconds.
  **Status: GREEN** (rc 0, 262 members) as of 2026-09-24.
* **Scoped `cargo check -p <crate>` in a scratch materialisation**, then delete the target dir — the
  approach the user asked for, to keep disk use small. Materialise with
  `git archive <tree> | tar -x -C G:/tmp/mcheck` (no deletions ⇒ guard-safe).
  **Cannot pass yet**: 117 files still carry conflict markers, so any build fails on syntax.
* Honest limit: only ~47 GB free and no `target/`. A cold full-workspace `cargo check` very likely
  does **not** fit. Prefer `cargo metadata --no-deps` for manifest validation, then scoped `-p`
  checks on the leaf crates that were actually resolved.
